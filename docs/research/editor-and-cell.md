## Редактор: конструкция и сохранение

В локальном EXE подтверждена основная таблица методов редактора `013f5800`:
`+0x2c → 00588570` (нажатие мыши), `+0x30 → 0058b650` (отпускание),
`+0x34 → 005737d0` (перемещение), `+0x3c → 0058be50` (кадровое обновление).
[Слова таблицы](evidence/editor-vtables/memory-words.tsv) сверены с обращениями к полям редактора.
`0058ba60`, ранее подписанная как возможный mouse move, — вспомогательный обработчик обновления;
метка в основной новой выгрузке исправлена.

[Сохранение `004af780`](evidence/editor-region/004af780.c) переводит рабочую модель в ресурс
со списком записей размером `0x1d8`. Каждая запись содержит:

* идентификаторы группы и части;
* индекс родителя и симметричной детали, либо `-1`;
* масштаб, положение, матрицы ориентации и пользовательского вращения;
* данные привязки к поверхности и асимметрии;
* значения управляющих деформаций, покраску и цвета.

Перед сохранением деталям присваиваются индексы. Ссылка на родителя/симметричную деталь сохраняется
только при проверке, что индекс находится в списке и указывает на тот же объект.
Деформационные каналы и палитры копируются ограниченными списками, в показанных ветвях — до 8.
[Загрузка `004ae8d0`](evidence/editor-region/004ae8d0.c) создаёт части и восстанавливает связи по индексам.
Это подтверждённая модель данных, а не сохранение готовой геометрической сетки.

В оригинальном редакторе используются родительские связи и геометрическое крепление.
Правила квадратной сетки и связности кубических сегментов для Minecraft по-прежнему предстоит
спроектировать как адаптацию. Из наличия `parentIndex` нельзя вывести универсальный запрет
всех свободно стоящих деталей для всех редакторов.

## Бюджет, покупка, возврат и история

Из инициализации редактора найдена таблица лимитов `013f56c0`, а не только предполагаемые
адреса из SDK. [Бинарная таблица](evidence/editor-vtables/memory-words.tsv) даёт следующие методы:

| Функция | Подтверждённое поведение |
|---|---|
| [0059e460](evidence/editor-focus-pass/0059e460.c) | Прочитать текущее значение выбранного лимита |
| [0059e470](evidence/editor-focus-pass/0059e470.c) | Проверить `requested <= available` |
| [0059e3c0](evidence/editor-focus-pass/0059e3c0.c) | Установить верхнюю границу |
| [0059e3e0](evidence/editor-focus-pass/0059e3e0.c) | Ограничить значение сверху, если граница ненулевая |
| [0059e400](evidence/editor-focus-pass/0059e400.c) | Прибавить изменение, применить ограничение, отправить уведомление |
| [0059e430](evidence/editor-focus-pass/0059e430.c) | Установить новое значение и уведомить при изменении |
| [0059e490](evidence/editor-region/0059e490.c) | Проверить бюджет и несколько видов сложности перед операцией |
| [0059e8d0](evidence/editor-focus-pass/0059e8d0.c) | Проверить дерево деталей вместе с симметричной ветвью |
| [0059e380](evidence/editor-drag-pass/0059e380.c) | Прибавить к бюджету стоимость детали из `part+0x5e4` |
| [0059e3a0](evidence/editor-drag-pass/0059e3a0.c) | Вычесть ту же стоимость |

Бюджет — индекс 0. Помимо него код проверяет ещё пять значений: сложность блоков, костей,
число определённых типов деталей, геометрическую оценку с округлением вверх и общее число частей.
Названия этих пяти категорий частично взяты из полей SDK; сами отдельные проверки видны в EXE.
`EnsureLimit` в исследованной реализации не ограничивает снизу нулём — это делает предварительная
проверка достаточности в вызывающем коде. Для нашей серверной реализации эту границу потребуется
проверять самостоятельно на операции, а не предполагать наличие общего clamp.

[00491800](evidence/editor-drag-pass/00491800.c) обходит дочерние и симметричные связи,
суммирует стоимость и использует список уже учтённых объектов. Поэтому стоимость группы
не следует вычислять как стоимость одной детали, умноженную на 2 без условий.
Численные цены берутся из ресурсов; конкретные цены всех клеточных частей пока не извлечены.

[00586410](evidence/editor-region/00586410.c) сохраняет снимок модели и отдельный снимок состояния
редактора. После undo новая фиксация удаляет дальнейшую ветку redo.
[00574080](evidence/editor-model-pass/00574080.c) включает в снимок бюджет, режим, тему и dirty-флаги;
[0057c2f0](evidence/editor-model-pass/0057c2f0.c) восстанавливает их, включая бюджет через метод лимитов.
[Undo](evidence/editor-region/0058a5a0.c) и [redo](evidence/editor-region/0058a950.c) загружают сохранённую
конструкцию обратно в рабочую модель. История — часть экономической операции, а не только картинки.

## Размещение, симметрия и изменение тела

[00588570](evidence/editor-focus-pass/00588570.c) различает деталь из палитры, существующую деталь,
активный handle и разные виды геометрии. Для существующей детали выполняются проверки лимитов;
затем создаётся соответствующий обработчик манипуляции. [0058b650](evidence/editor-focus-pass/0058b650.c)
завершает операцию, фиксирует историю при изменении модели; в одной из ветвей вызывает undo.
Полное условие этой ветви ещё требует восстановления типов: сырой псевдокод содержит плохие локальные переменные.

Для одного пути перетаскивания прослежена цепочка:

`00588570 → 005aacf0 / 005aabc0 → vtable 013f710c → 005ab860`.

Параметр редактора `+0x2f0` передаётся обработчику и сохраняется в его флаг `+0x44`.
В SDK он называется `mbCellPinningToRigBlocks`; бинарные обращения подтверждают отдельное
поведение крепления, но не сами по себе все правила клеточного редактора.

[005ab860](evidence/editor-drag-methods/005ab860.c) использует луч камеры, запрос к оболочке,
положение курсора, текущего родителя, симметрию и повторно применяет ориентацию/привязку.
[004a4180](evidence/editor-attachment-pass/004a4180.c) исключает саму деталь и её симметричную пару
из поиска кандидатов, затем выбирает подходящего кандидата по расстоянию и предикату `004a1dc0`.
[004a1dc0](evidence/editor-message-pass/004a1dc0.c) проверяет атрибут `0x2b`, совместимость деталей
через вспомогательные функции, расстояние и, в одной из ветвей, скалярное произведение
векторов из матриц ориентации `> 0.5`. Назначение конкретных осей и все ветви совместимости
ещё не расшифрованы; это не принято за универсальное правило «угол детали меньше 60 градусов».
[004a2860](evidence/editor-attachment-pass/004a2860.c) участвует в перепривязке, отвязке и обновлении позы.
Это ещё не восстановление полного предиката допустимости крепления.

`005aa690`, первоначально помеченная как возможная проекция курсора, на деле выбирает крайние
позвонки по Y и ограничивает целевую позицию центральной линией между ними; внутри диапазона
присваивает X=0. Это показывает необходимость отделять общую механику тела от клеточного pinning.
[00582250](evidence/editor-region/00582250.c) содержит изменение через handles и отдельные ветви
для позвонков/частей; все коэффициенты изменения формы и ограничения радиусов ещё не разобраны.

## Как части становятся характеристиками клетки

Подтверждена цепочка `00e679e0 → 00e83e30 → 00e52040`:
загрузка данных организма → получение игровых частей → пересчёт агрегированных характеристик.
[00e83e30](evidence/cell-region/00e83e30.c) читает до 64 записей `RigblockData` размером `0x8c`,
преобразует положение/границы/ориентацию и создаёт записи по `0x48` байт для симуляции клетки.
При этом игровая координата Z явно обнуляется в показанной ветви.

[Классификатор 00e82770](evidence/cell-region/00e82770.c) проверяет свойства ресурса части.
Соответствие имён ниже дополнительно сверено с enum клеточных частей в SDK:

| Тип | Интерпретация | Счётчик относительно объекта данных организма |
|---:|---|---|
| 2 | Хищный рот | `+0x120c` |
| 3 | Фильтрующий рот | `+0x1210` |
| 4 | Хоботок | `+0x1214` |
| 5 | Химическая способность | `+0x1218` |
| 6 | Электричество | `+0x121c` |
| 7 | Шип | `+0x1220` |
| 8 | Реснички | `+0x1224` |
| 9 | Жгутик | `+0x1228` |
| 10 | Jet | `+0x122c` |
| 11 | Глаз | `+0x1230` |
| 12 | Тело | `+0x1234` |

Это эффективные счётчики, а не просто длина списка: `00e52040` прибавляет **2**, когда флаг
записи истинный, и **1** иначе. `00e83e30` получает этот флаг из `mSymmetricIndex == -1`.
Перевод этих эффективных единиц в отображаемое количество частей нельзя опускать.

[00e52040 после уточнения сигнатуры](evidence/cell-typed-pass/00e52040.c) вычисляет:

* доступность двух типов питания по наличию ртов, флаг контактного оружия по шипам;
* параметр обнаружения через кривую `0x77540c34` от эффективного количества глаз;
* маску движения и скорость по сочетанию двигательных органов;
* параметры электрических и химических способностей через другие кривые;
* геометрический центр, радиус охвата и вспомогательные индексы частей.

Для движения обозначим эффективные счётчики `C` (реснички), `F` (жгутики), `J` (jet), а `gNN` —
поле globals со смещением NN. Приоритет формулы скорости:

```
J > 0: curve(0x2c574746, J + F*g78 + C*g74)
F > 0: curve(0xbbab1bf5, F + C*g80)
C > 0: curve(0x2ef68471, C)
иначе: globals.noPartSpeed (+0x90)
```

Маска содержит биты `F → 1`, `C → 2`, `J → 4`. Без органов выбирается бит 1 и скорость
`noPartSpeed`. Это объясняет ветвление физики в первом проходе. Формулы не линейны по числу
органов: итог проходит через настроечную кривую.
[00e837c0](evidence/cell-typed-pass/00e837c0.c) ищет такую кривую в prop-списке `0xc951eb63`,
берёт крайнее значение за пределами диапазона и интерполирует между соседними точками.
Точные точки этих кривых из установленных `.package` ещё не извлечены.

[00e686c0](evidence/cell-typed-pass/00e686c0.c) использует параметр глаз в радиусах обнаружения
для одного типа AI и умножает радиусы на масштабный коэффициент. Другие типы AI берут
awareness из своих настроек. Следовательно, правило «каждый глаз всегда добавляет одинаковый радиус»
этим кодом не подтверждается.

## Еда, здоровье, прогресс и бюджет клеточного редактора

[00e7d760](evidence/cell-region/00e7d760.c) выделяет ветвь игрока и вызывает
[00e7d070](evidence/cell-typed-pass/00e7d070.c). В обработчике награды подтверждено:

1. Здоровье игрока ограничивается сверху **6**.
2. Для отсутствующего специального ресурса еда восстанавливает 2 HP и даёт 10 прогресса.
3. При наличии ресурса используются `hpValue` (`+0x310`) и `eatFoodValue` (`+0x30c`).
   В режиме saved mode=0 восстановление по ресурсу умножается на 2.
4. Нулевой `eatFoodValue` завершает обработку до прибавления прогресса.
5. Затем вызывается [00e7ce10](evidence/cell-typed-pass/00e7ce10.c) с целым количеством и флагом вида пищи.

`00e7ce10` прибавляет количество к `saved+0x1c`, ограничивает сверху 1000 и отдельно учитывает
излишек в `+0x24` либо `+0x28`. Для одного вида пищи растёт счётчик `+0x20`.
Режим определён как целочисленная прибавка по `ADD [saved+0x1c], EDI`; исходная float-сигнатура
декомпилятора была неверна. Условие распределения растительной/животной пищи зависит также
от типа поглощённого объекта и рта; полного именования всех вариантов пока нет.

[00e51410](evidence/cell-typed-pass/00e51410.c) берёт пороги и значения из таблицы прогрессии,
интерполирует между строками и возвращает целое значение. На порогах 0,50,100,150,...,1000
эта величина равна 0,5,10,13,...,65. Это уже связано с бюджетом двумя прямыми цепочками:

* [Вход 00e59800](evidence/cell-typed-pass/00e59800.c): `available = currencyCurve(progress) - savedSpent`;
  далее [00e84600](evidence/cell-typed-pass/00e84600.c) создаёт `EditorRequest`, передаёт модель,
  collectable/unlock-данные и отправляет бюджет отдельным сообщением `0x90a03fdf`.
* [Ответ 00e809a0](evidence/cell-typed-pass/00e809a0.c): проверяется контекст `0x01100000`;
  в ветви подтверждения `savedSpent = currencyCurve(progress) - returnedBudget`.
  Затем сохраняется ключ модели и организм пересоздаётся через `00e7fd00`.

`savedSpent` находится в `saved+0x2c`. Бюджет не следует путать с `EditorRequest+0x60`:
в показанном вызове это float-параметр масштаба/редакторского контекста, а бюджет передаётся отдельно.
[Обработчик сообщения 00591fa0](evidence/editor-message-pass/00591fa0.c) найден по реальному
указателю `013f57c4` в `.rdata`, который автоанализ не превратил в xref.
В [ASM](evidence/editor-message-pass/00591fa0.asm) по `00592fd1..00592fe9` берётся поле сообщения `+8`
и вызывается `limits.SetValue(0, messageBudget)`. Здесь `this` указывает на интерфейс редактора
со смещением `+0x10`, поэтому поле лимитов читается как `this+0x424`, а не `editor+0x434`.
Это закрывает промежуточную передачу между входом в клеточный редактор и системой бюджета.
`00e61140 → 00e83910 → 00e828c0` с прибавкой 50 — **отдельный путь перехода в CreatureGame**,
что подтверждается `00e828c0` и идентификатором `01654c01`. Он не принят за обычный вход в редактор клетки.

## Качество восстановления и оставшиеся границы

* Новые функции создавались в базе Ghidra только при наличии нативного CALL или указателя
  из области данных. Для отсутствующих инструкций выполнялась статическая дизассембляция.
  [Журнал](evidence/editor-function-definitions-final/defined-functions.tsv) сохраняет источник ссылки.
  Два пропущенных метода дополнительно определены по проверенным сырым указателям
  [013f57c4 и 013f92e4](evidence/editor-message-definitions/defined-functions.tsv): скрипт сверяет
  фактическое 32-битное значение в инициализированной неисполняемой памяти с адресом функции.
* При выгрузке ASM/xref теперь включаются блоки, достигнутые декомпилятором, даже если
  автоанализ не включил их в первоначальное тело функции. Раньше ASM мог быть короче C-пути.
* Две сигнатуры помечены аналитиком по стеку, вызовам и RET;
  [до/после и основания](evidence/verified-cell-signatures/signatures.tsv) сохранены отдельно.
  Это не восстановленные оригинальные имена. Скрипт отказывается применять их к другому MD5.
* Остались повреждённые типы, косвенные вызовы и возвраты через XMM0. Внутри `00e837c0`
  некоторые локальные аргументы всё ещё восстановлены неверно; подпись функции улучшает вызывающий C,
  но не устраняет все ошибки её тела. Число `OK` не является оценкой семантической точности.
* [Неразрешённые запросы](decompilation-unknowns.csv): два отброшенных адресных зонда.
  Они не включены в 1155 успешных адреса. Два адреса SDK, ранее не распознанные Ghidra,
  удалось подтвердить по сырым указателям и успешно декомпилировать.
* Дальше нужны расшифровка атрибутов и помощников предиката `004a1dc0`, правил pinning и перестройки тела,
  извлечение цен/кривых из ресурсов, полный разбор unlock-условий,
  всех боевых контактов и runtime-проверка контрольных сценариев в Spore.

Карта типов сверялась с первичными материалами проекта
[Spore-ModAPI: Editor](https://github.com/Spore-Community/Spore-ModAPI/blob/master/Spore%20ModAPI/Spore/Editors/Editor.h),
[таблицей адресов](https://github.com/Spore-Community/Spore-ModAPI/blob/master/Spore%20ModAPI/SourceCode/DLL/AddressesEditors.cpp),
[EditorResource](https://github.com/Spore-Community/Spore-ModAPI/blob/master/Spore%20ModAPI/Spore/Editors/cEditorResource.h)
и [CreatureDataResource](https://github.com/Spore-Community/Spore-ModAPI/blob/master/Spore%20ModAPI/Spore/Editors/cCreatureDataResource.h).
Это сторонняя карта: итоговые утверждения выше привязаны к локальному бинарному коду.

в игнорируемых папках. Перенос оригинального C-кода в Java не выполнялся.

## Проверка и перенос 2026-10-21

Ghidra повторно открыла постоянный проект и успешно декомпилировала все 9 функций
из `requests/cell-typed-pass.txt`: [статусы](evidence/cell-verification-20261021/decompile-status.tsv).
Повторный проход не увеличивает число уникальных адресов.

В Java реализованы таблица заработанной ДНК `e51410`, относительные категории размера
`e57340`, таблицы урона `e58980`, предел прогресса 1000 и фиксированное здоровье 6.
Начисление при поедании — разница значений кривой до/после пищи, поэтому расход ДНК
в редакторе не мешает дальнейшему заработку. Округление Java `Math.rint` остаётся
предположением для точных пограничных значений FPU. Скорость, радиус видимости,
порог открытия всеядности и время защиты после удара пока используют настройки
прототипа; оригинальные ресурсные кривые не восстановлены.

Отдельный режим запускается из главного меню в собственном сохранении. Сеточный
редактор адаптирует связность к кубикам, поддерживает зеркальное размещение и отмену;
русские подписи, пояснения частей и объёмный предпросмотр добавлены сразу.
Нативная система свободного перетаскивания и крепления деталей ещё не перенесена
целиком. Последующих игровых стадий в моде нет.
