# Проверка 0.5.0 — 21 октября 2026

* 20 JUnit: начальный каталог, шесть закрытых органов, проверка разрешений,
  миграция установленного органа и прежнего открытия всеядного рта.
* Серверный сценарий дополнен физическим фрагментом, сохранением его метаданных,
  подбором, отсутствием повторной награды, добычей из NPC, запретом закрытого
  органа при поддельном apply и сохранением открытий в профиле.
* В пищевом участке сценария после проверки движения сбрасываются только
  тестовые счётчики еды/ДНК, чтобы случайная еда по пути не влияла на проверку
  ровно пяти подготовленных порций.
* Редактор: закрытая кнопка недоступна; прямой вызов выбора не меняет чертёж.
* Клиентский игровой сценарий подбирает ядовитый орган, получает серверное
  разрешение и уведомление, затем выбирает его через вторую страницу каталога,
  размещает на потомке и проверяет списание цены. Скриншот `cell-discovery-*`.

# Проверка 0.4.0 — 21 октября 2026

Дополнительно к сценариям ниже:

* 17 JUnit: добавлены связность и уникальность 24 чертежей NPC и покрытие 12 типов органов.
* Серверный GameTest способностей: электрический урон, оглушение, иммунитет,

  снизу и со стороны полюсов, сброс камеры, доступность пяти новых деталей
  на второй странице каталога.

  каждого уровня 6–10. Дополнительный счётчик контролирует дистанцию тумана
  в момент рисования клетки. Сохраняются `cell-level-6-*` … `cell-level-10-*`.

# Проверка 0.3.0 — 21 октября 2026

Minecraft 1.21.1, Fabric Loader 0.16.10, Fabric API 0.115.1+1.21.1, JDK 21, Gradle 8.12.

| Проверка | Результат |
|---|---|
| `test build` | 16 JUnit без ошибок; сборка remapped JAR успешна |
| `runEditorTest` | Настоящий GUI: кубическое тело, поверхностная деталь, зеркальная пара, масштаб 1,5, поворот Y/X/Z, перенос на другой сегмент с сохранением позы, удаление, undo/redo, бюджет |
| `runGametest` | Сервер: отказ редактора/зова до еды, 5 порций пищи, ДНК, партнёр/яйцо, допуск после размножения, применение трансформированного глаза, поколение/история и NBT round-trip, отказ повторного применения, рост, урон/смерть, возврат |
| `runDedicatedTest` | Одиночный клиент через кнопку отдельного мира: выбор хищника, WASD, реальный обработчик удержания ЛКМ, зов, экран эволюции, редактор, сетевое применение, потомок и NBT, невозможность `/cell leave` в отдельном мире, синхронизация HP атакуемой цели |
| `runWorldTest` | Тот же цикл в обычном мире с `/cell enter`; выход восстанавливает камеру и обычный инвентарь |

Сценарии клиента сохраняют снимки `cell-world-*`, `cell-evolution-*`,
`cell-editor-3d-*`, `cell-offspring-*`, `cell-combat-*` в каталогах
`build/dedicatedtest/screenshots`, `build/worldtest/screenshots`,
`build/clienttest/screenshots`. Журналы — `logs/latest.log` в этих каталогах запуска.
`runDedicatedTest` означает отдельный режим в **интегрированном** сервере клиента;
это не проверка подключения двух процессов к внешнему dedicated server.

Для воспроизводимости клиентский сценарий выдаёт прогресс/еду перед зовом и
подготавливает неподалёку жертву для проверки HP. Получение пищи и начисление ДНК
проверяются отдельно настоящим серверным GameTest. В тесте сервера партнёр
сближается искусственно; в клиентском сценарии он подплывает самостоятельно.
GLFW-курсор и нажатие подаются также через настоящие обработчики Mouse, поскольку
неактивное тестовое окно не всегда получает системное событие перемещения.
Test-only классы и mixin не входят в распространяемый JAR.

Границы: нет проверки нескольких клиентов и повторного входа того же UUID после
полного перезапуска JVM. Проверены сериализатор/десериализатор PersistentState,
JSON старых конструкций и штатное сохранение мира при выходе. В журнале остаётся
сообщение Minecraft о незарегистрированном data fixer собственной сущности;
проверенная миграция профиля реализована в CellSave, это сообщение не является
падением теста. Полное совпадение со Spore этими проверками не заявляется.

Снимки находятся в `build/worldtest/screenshots/cell-world-<timestamp>.png`,
`cell-evolved-<timestamp>.png` и `build/clienttest/screenshots/cell-editor-<timestamp>.png`.
Просмотрены снимки мира с видимой клеткой и редактора с чёткой сеткой/подписями.
Снимки имеют уникальные имена, чтобы повторный запуск не перезаписывал открытые просмотрщиком файлы.

Отчёты: `build/test-results/test/`, `build/gametest-results.xml`;
журналы клиентских сценариев: `build/worldtest/logs/latest.log`, `build/clienttest/logs/latest.log`.

Исправленные по результатам реального запуска проблемы:

* mixin вынесен из общего пакета клиентских классов, который Mixin запрещает загружать напрямую;
* камера включает третье лицо для отображения самой управляемой сущности;
* отключён стандартный blur фона редактора, размывавший уже нарисованную сетку;
* редактор использует G, сохраняя стандартную привязку инвентаря;
* test-only пресет дополняет ограничения GameTest 1.21.1 по загрузке дополнительных измерений.

Рамки проверки: сохранение проверено через настоящий сериализатор/десериализатор PersistentState
и штатное сохранение одиночного мира. Отдельный сценарий перезапуска JVM с повторным входом
того же UUID не выполнялся. Одновременная игра нескольких клиентов пока не проверена.
